# Releasing a version

The steps for every release, in order. Each one is here because skipping it once caused a
problem on a real server.

## 1. Code

1. Merge the release branch into `main`; `npm run typecheck`, `npm test` and `npm run build` pass.
2. Set the version in `package.json` (and the two root entries of `package-lock.json`), commit
   `Release X.Y.Z`, tag `vX.Y.Z`, push `main` and the tag.

## 2. Bundle

```powershell
.\scripts\build-offline-bundle.ps1 -Compress
```

- Writes `dist-offline\sbom-platform-offline-X.Y.Z.zip` **and** its `.sha256` file. That file is
  the only source of the checksum: upgrade scripts, manuals and release notes take it from there,
  never typed. (The 0.5.0 manual once carried 0.4.0's checksum and told people a good zip was
  damaged.) Check that every file that names a checksum has this one:
  ```powershell
  $sha = (Get-Content dist-offline\sbom-platform-offline-X.Y.Z.zip.sha256).Split(" ")[0]
  Select-String -Path dist-offline\upgrade-to-X.Y.Z* -Pattern $sha
  ```
- Also writes `windows\*-paste.txt`: the Windows scripts as blocks to paste, for servers whose
  Group Policy requires signed scripts. Generated by `scripts/make-paste-scripts.ps1`; never
  edit them by hand.
- Confirm the zip holds no secrets: no `.env`, `CREDENTIALS.txt`, `*.key`, `*.pem`, dumps or
  backups (`linux\backup.sh` and its units are expected).

## 3. Rehearse

```powershell
.\scripts\upgrade-rehearsal.ps1 -FromBundle dist-offline\sbom-platform-offline-<previous> `
    -ToApiImage sbom-platform/api:X.Y.Z -ToWebImage sbom-platform/web:X.Y.Z -SkipBuild
```

All checks must pass. When `deploy/windows` or `deploy/linux` changed, also install into
Hyper-V on a test server: a new install, a move with `-MigrateFrom` from a Docker Desktop
installation that has a `docker-compose.override.yml` (HTTPS on 443 with files outside its
folder), an upgrade, and `-Resume` after a start that failed for lack of memory.

## 4. Publish

On the GitHub release `vX.Y.Z`:

- the release notes (with the checksum from the `.sha256` file);
- **the assets** - the zip, its `.sha256`, and the upgrade script and manual for Docker Desktop
  installations. Releases 0.4.0 to 0.5.0 went out without the zip, and a server then had no
  place to download it from:
  ```powershell
  gh release upload vX.Y.Z dist-offline\sbom-platform-offline-X.Y.Z.zip `
      dist-offline\sbom-platform-offline-X.Y.Z.zip.sha256 dist-offline\upgrade-to-X.Y.Z.ps1 `
      dist-offline\upgrade-to-X.Y.Z.cmd dist-offline\upgrade-to-X.Y.Z-manual.txt
  ```

## 5. Release notes: what a server administrator needs

- whether the database changes (and from which versions the upgrade starts);
- for Windows Server: `upgrade-windows.cmd`, or `windows\upgrade-windows-paste.txt` where
  scripts must be signed;
- anything the administrator has to do by hand, or "nothing".
